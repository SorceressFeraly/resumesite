Practice Range

The practice range was an onboarding feature created to decrease initial churn during playtests. The team was given three weeks to create a level that could be accessed offline and would teach the players the basics of the game.

Looking at player comments from Discord and form surveys done from the previous playtest, it was clear that one of the main pain points of introducing the game was the lack of an onboarding. This made it difficult to get proper feedback as players would give up before understanding the complex game loop properly.
I confirmed this by looking at metrics compiled from Snowflake, where it was clear that ~30% of players that got into a game churned before reaching the end game screen. This also had a negative effect on the players that did grasp the game as they would be plagued by uncoordinated players and/or leavers on their teams.

The practice range was proposed to combat this problem.
While we didn't have time to create an advanced onboarding flow in pre-alpha, we wanted to present an offline playground where players could get used to the unique movement, the rules of the game loop, and try out the guns and hero abilities before getting into a proper match.

I took responsibility for planning and designing the feature along with setting the scope and coordinating the team through Jira. I worked with the level designer, UX designer, programmers, and artists to make sure we could deliver the best possible product under a tight timeframe.

The main issue we had to tackle was that the entire game had been built to be ran in a snapnet multiplayer online server environment. The programmers had to translate the game state to a single player environment where a lot of exceptions had to be made to accomodate a seemless transition to the player.
I worked close with the programmers, checking in daily what they needed and when changes rapidly needed to be made to the design in order to get all parts of the feature working in time.
